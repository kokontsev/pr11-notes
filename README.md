# Практическая работа 11

Проектирование REST API для заметок.

Сервис разделён на HTTP-обработчики, бизнес-логику и репозиторий. Хранилище в памяти защищено RWMutex; список отсортирован по ID. Реализованы все пять CRUD-маршрутов, поиск по заголовку и пагинация. Вход ограничен 1 МиБ; лишние поля и несколько JSON-объектов отклоняются.

## Запуск на macOS или Linux

Go 1.27.1, curl. Каждая практика — отдельный Go-модуль. Команды выполняются из этой папки.

```bash
go test ./...
go vet ./...
go run ./cmd/api
```

Файл `.env` читается оболочкой через `source`; автоматически сервер его не загружает. Порт API по умолчанию 8080. При одновременном запуске меняйте HTTP_ADDR, APP_ADDR (ПР9) или APP_PORT (ПР10).

## Проверки

Фактические результаты находятся в `evidence/`. Полные curl-команды и ответы — в `evidence/requests.txt` (для практик с HTTP-проверками). Тесты 15 и 16 записаны в `evidence/tests.txt` и `evidence/integration.txt`.

Маршруты: POST/GET `/api/v1/notes`, GET/PATCH/DELETE `/api/v1/notes/{id}`. Поиск `?q=Go`, страницы `?page=1&limit=20`. Тело создания: `{"title":"Go","content":"Текст"}`.

## Подготовка к защите

REST — Representational State Transfer: взаимодействие с ресурсами через единообразный HTTP-интерфейс.

CRUD соответствует POST, GET, PATCH/PUT и DELETE. Создание возвращает 201, удаление без тела — 204.

HTTP-слой разбирает запрос; сервис проверяет бизнес-правила; репозиторий хранит данные. Интерфейс репозитория позволяет менять реализацию.

Stateless означает, что каждый запрос содержит необходимые данные для обработки. Это не запрещает серверу хранить сами ресурсы.

Стандартные статусы упрощают обработку клиентом. Версионирование /api/v1 позволяет развивать контракт; JWT подключается middleware.
